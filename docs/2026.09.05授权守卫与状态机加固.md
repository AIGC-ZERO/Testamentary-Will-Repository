## 0. 背景

9 月 3 日安全分析发现：所有 `admin/*` 接口只校验"任意有效 JWT"，普通 H5 用户可越权调用后台接口；`/api/auth/login` 存在免密管理员入口（`role='2'`）；开发固定验证码在生产配置缺失时仍生效；无登录/短信频控。本次会话按总计划 §2.3/§2.5 落地 **角色守卫（RolesGuard）+ 服务端状态机强制**，并一并关闭两个认证旁路、补齐限流与锁定。

### 1.2 状态机强制（新）

| 文件 | 说明 |
|------|------|
| `backend/src/common/state-machine.ts` | `assertStatusIn` 校验当前状态→非法流转抛 **409 Conflict**；五套流转规则（登记/见证/纠纷/加盟/业务单）；所有 `admin` 写操作先查存在性（不存在抛 **404**，替代原 Prisma P2025 的 500） |

- **登记**：`已受理`/`驳回终止` 为终态；退回补充不可重复退回；受理/驳回/退回均限审核态来源。
- **见证**：`待审核→待排期→已完成`；`complete` 额外要求已排期（`scheduleAt` 非空）。
- **纠纷**：线性 `调解中→取证中→诉讼中→已结案`，终态与未知阶段均 409（原实现终态静默停留）。
- **加盟**：仅 `待审核` 可入库/驳回。
- **业务单**：`00→01→02` 逐级；`10/11/02` 终态。

### 1.3 认证旁路关闭 + 限流锁定

- **删除 H5 `role='2'` 免密管理员分支**（改为 400 + 引导后台登录页）。前端 H5 登录页已有失败兜底（跳转 `/admin/login`），无兼容问题。
- **开发万能码硬化**：`SMS_DEV_CODE` 仅在 `NODE_ENV != production` 时生效（`devSmsCode()` 兜底）；生产环境验证码一律随机生成。
- **登录锁定**：H5 登录与后台登录按账号累计失败（5 次/10 分钟，成功清零），超限 429。
- **短信频控**：同手机号 1 分钟 1 次、1 小时 5 次，超限 429。
- **后台令牌短寿命**：`JWT_ADMIN_EXPIRES_IN`（默认 `2h`，`.env.example` 已补），与 H5 用户 `7d` 分离。

### 1.4 IDOR 修复

`POST /businesses/:orderCode/cancel`：原任意登录用户可作废任意业务单。现校验 `userId === 当前用户 sub`（历史无归属数据禁止用户侧作废，403）。

## 2. 验证结果

**单元测试 27/27 通过**（新增三个测试文件，均不依赖数据库）：

| 文件 | 覆盖 |
|------|------|
| `src/common/state-machine.spec.ts` | 各状态机允许/拒绝路径、终态、跳步攻击 |

**真实 API 冒烟（本机 Docker Postgres + dist 启动）全部符合预期**：

| 场景 | 结果 |
|------|------|
| 无 token 访问 admin | 401 |
| `role='2'` 免密登录 | 400（后门已关） |
| 用户 token 访问 `admin/*` | 403 |
| 用户 token 伪造 `role=管理员` | 403（kind 强校验，伪造无效） |
| 审核员访问 `admin/users`（仅管理员） | 403 |
| 业务员 approve 见证（仅审核员） | 403 + 审计留痕 |
| 登记 approve 二次/终态 supplement/reject | 均 409 |
| 见证未排期 complete | 409；完整流转 approve→schedule→complete→重复 complete | 201×3 → 409 |
| 用户取消他人/无归属业务单 | 403；取消自己 → 201；重复取消 → 409 |
| 短信 1 分钟内第 2 次 | 429 |
| 后台登录连续失败第 6 次 | 429，且 5 次失败均有审计 |
| 不存在 ID 的 admin 写操作 | 404（原为 500） |

审计库抽查：`后台登录失败`×5、`越权拦截 ……（role=业务员）` 均正确落库。
